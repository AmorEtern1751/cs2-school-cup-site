Build a complete, responsive Russian-language website for a 16-team school CS2 tournament.

IMPORTANT: The entire website must be in Russian: all UI text, buttons, labels, statuses, navigation, demo data and admin panel. Use English only for code identifiers.

**Design:** Premium esports aesthetic inspired by FACEIT/HLTV. Dark graphite background, orange accents, clean typography, compact cards, subtle animations. Fully responsive desktop/mobile layout.

**Tournament:**
- 16 teams, single-elimination bracket.
- Round of 16, quarter-finals, semi-finals, third-place match and grand final.
- All matches are BO3 except the grand final, which is BO5.
- Display teams, logos, match time, score and status: «Скоро», «LIVE», «Завершён».
- Clicking a match opens detailed match information: map scores, current map, round score, player stats (K/D/A, ADR, headshots, MVP) and a Twitch stream button.
- Winners automatically advance to the next round. Third-place match uses the semi-final losers.

**Admin panel:** Add a functional demo admin panel to edit teams, schedules, scores, map results, player stats and Twitch links. Update the bracket when results change. Save changes in localStorage. Clearly label demo data; never pretend it is live server data.

**Technical requirements:** React + TypeScript + Vite + Tailwind CSS. Use reusable components, typed data models and clean architecture. Separate UI components from tournament logic and demo data. Include 16 sample teams and realistic Russian-language UI content. All navigation, filters, match cards and admin controls must work. Include loading, empty and error states where appropriate.

Do not implement authentication, paid services, a backend or real CS2 integration yet. Keep the data layer modular so Supabase and a CounterStrikeSharp server plugin can be added later.

Build the actual working application, not a static mockup. Run it, check for errors, and fix broken interactions. Prioritize a polished design and working tournament bracket over unnecessary features. Do not ask questions; make reasonable decisions and finish the implementation.
